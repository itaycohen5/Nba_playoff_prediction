# Playoff Predict — חזרה לפיתוח מקומי

סימולטור פלייאוף NBA עם חשבון משתמש, ארנק מדומה, הימורים מדומים ובראקט. אין כסף אמיתי.
היישום המקומי פועל מקובץ נתוני העונה המצורף ואינו דורש Railway, Supabase או שירות AI.

## שפה ונגישות

בראש כל עמוד ניתן לבחור עברית או English. השפה וכיוון הקריאה נשמרים בדפדפן.
כפתור הנגישות קבוע בפינה השמאלית התחתונה בשתי השפות ובמובייל. הוא מאפשר הגדלת
תצוגה עד 200%, ניגודיות גבוהה, הדגשות, ריווח קריאה, גווני אפור וצמצום תנועה.
Esc סוגר את התפריט ומחזיר את המיקוד לכפתור. העדפות נגישות נשמרות בדפדפן בלבד.

הצהרת הנגישות זמינה ב־`/accessibility` ומהתפריט ומהכותרת התחתונה.
לפני פתיחה לציבור יש להשלים ערוץ קשר אמיתי באמצעות `NEXT_PUBLIC_ACCESSIBILITY_EMAIL`
ואת שם המפעיל באמצעות `NEXT_PUBLIC_SITE_OPERATOR`, בסביבת Next.js בזמן build.
התפריט אינו אישור לעמידה בחוק. יש להשלים בדיקת נגישות מתאימה, לרבות שימוש בטכנולוגיות
מסייעות, ולבחון את תחולת הדרישות והפטורים על השירות. המיקום השמאלי נבחר לפי בקשת
בעל הפרויקט; אין כאן טענה שהדין מחייב מיקום מסוים לכפתור.

## הפעלה

יש ליצור סביבת Python נקייה ולהתקין את requirements.txt. להריץ מתוך שורש הפרויקט:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c constraints-tested.txt
.\.venv\Scripts\python.exe main.py
~~~

בחלון נוסף, מתוך web_client:

~~~powershell
npm.cmd ci
npm.cmd run dev
~~~

האתר זמין בכתובת http://localhost:3000 והשרת בכתובת http://127.0.0.1:8000.
יש להירשם דרך המסך. אין משתמש דמו או סיסמה קבועה. הוראות סביבת המסד והאימות נמצאות בהגדרות השרת;
אין להעתיק קובץ .env מהארכיון למערכת ציבורית או לפרסם מפתחות.

## מה המנוע מחשב

המנוע הפעיל הוא סימולטור סטטיסטי שמבוסס על data/team_stats.csv. דירוג ההתקפה,
קצב המשחק והריבאונד מחושבים מסכומי העונה. דירוג ההגנה הוא אומדן לפי נקודות היריב
והפוזשנים המשוערים. לוח הפלייאוף המוגדר בקוד הוא תרחיש מותאם, ואינו טענה לדירוג רשמי.

סיכוי הניצחון המשמש להגרלת המשחק משמש גם לחישוב יחסי moneyline. יחסי סדרה מביאים
בחשבון את המצב הנוכחי, ביתיות ומומנטום. הניקוד והקווים הם מודל סימולציה מקורב, ללא
טענה לכיול מקצועי. קובץ ה־ML הישן אינו משמש את האתר. נתונים חסרים או לא תקינים עוצרים
את המנוע בהודעת שגיאה ברורה במקום להחליף את הקבוצות בנתוני דמה.

## עיבוד נתונים ואימון — אופציונלי

הכלים הנפרדים דורשים requirements-pipeline.txt. התקנה זו אינה נדרשת להפעלת האתר.
לבניית פיצ'רים ואימון על הנתונים שכבר נשמרו:

~~~powershell
python -m pip install -r requirements-pipeline.txt
python scripts/run_pipeline.py
~~~

להורדת נתונים חדשים במפורש יש להוסיף --fetch. ההורדה משתמשת בעונת 2025-26,
עם שלושה ניסיונות לכל היותר וזמן המתנה מוגבל לכל בקשה; אינה מתבצעת בהפעלת היישום.
העיבוד מאמת סכימה, זוג בית/חוץ וייחוד משחקים ושומר פלט באופן אטומי.
האימון מפצל כרונולוגית לתקופות, ומבצע scaling רק על קבוצת האימון. פלטים ישנים
חסרי GAME_DATE מחייבים הרצת ETL מחדש. המודל נשאר כלי ניסויי נפרד.

## בדיקות

~~~powershell
python -m pip install -r requirements-dev.txt -c constraints-tested.txt
python -m pytest -q
~~~

יש להריץ בדיקות מול מסד זמני בלבד. אין להשתמש במסד חיצוני קיים לצורכי בדיקות.

## מסד נתונים, חשבון והיסטוריה

ברירת המחדל היא `nba_local.db` בתוך תיקיית הפרויקט. קובץ `.env` מהגיבוי אינו נטען
אוטומטית, ולכן הפעלה מקומית אינה מתחברת לשירותי האחסון הישנים. החשבון נשמר בסשן
עם Cookie מסוג HttpOnly למשך שמונה שעות. לכל משתמש טורניר אישי; יציאה מבטלת את הסשן.
יתרות נשמרות בסנטים שלמים. הימור או פעולה שנשלחו שוב עם אותו מזהה אינם מחויבים שוב.
פתיחת עונה חדשה מארכבת תוצאות ומחזירה הימורים פתוחים, בלי למחוק היסטוריה.

מסד SQLite ישן אינו משודרג אוטומטית. אם רוצים לייבא אותו, יש להריץ:

~~~powershell
python scripts/migrate_legacy.py old.db imported.db
$env:DATABASE_URL = 'sqlite:///C:/absolute/path/imported.db'
python main.py
~~~

הכלי שומר את המקור ללא שינוי, דורש יעד חדש, משמר חשבונות ויתרות, מבטל ומחזיר הימורים
ממתינים ומעתיק את ההיסטוריה המשותפת הישנה לארכיון של כל משתמש. נתונים ישנים שאינם
עומדים באילוצים עוצרים את הייבוא; המקור נשאר זמין. יש לבחור יעד חדש לאחר תיקון הנתונים.
בקובץ הישן לא נשמר תאריך הימור; עבור הימורים מיובאים התאריך המוצג הוא תאריך הייבוא.

`APP_ORIGINS` מגדיר את כתובות האתר המורשות לבקשות (ברירת המחדל: localhost:3000
ו־127.0.0.1:3000). `BACKEND_URL` מגדיר את כתובת השרת עבור ה־proxy של Next.js.
האפשרויות מתועדות ב־`.env.example`; יש להגדירן במשתני הסביבה של תהליך ההפעלה.
לגישה מאתר HTTPS יש להגדיר `COOKIE_SECURE=true` ואת כתובת האתר המדויקת.

לתמיכת PostgreSQL אופציונלית יש להתקין `requirements-postgres.txt` ולהגדיר
`DATABASE_URL` במפורש. ניהול כתיבות משתמש בנעילת שורת המשתמש. מסלול זה לא נבדק
מול שרת PostgreSQL חי; בדיקות המקביליות המקומיות בוצעו מול SQLite.

`constraints-tested.txt` מתעד גרסאות שנבדקו עם Python 3.14 ב־Windows עבור האתר
והבדיקות, ואינו נעילת גרסאות של כלי ה־ML האופציונליים.


## עיצוב Taste

הממשק עודכן לפי `design-taste-frontend` מתוך https://github.com/Leonxlnx/taste-skill.
דף הבית משתמש בכיוון borrowed-category, ומסכי העבודה בסגנון data-terminal.
הצבעים המקוריים נשמרו. קובצי העיצוב הפעילים: taste-app.css, taste-dashboard.css,
taste-page.css ו-accessibility.css. הצהרת הנגישות, בחירת השפה והעדפות התצוגה נשמרו.
גופן Noto Sans Hebrew מאוחסן מקומית עם רישיון OFL בתוך public/fonts; אין קריאה לשירות גופנים חיצוני.
תמונות המוצר הן צילומי מסך של חשבון הדגמה מקומי. נתוני מחשבון דף הבית הם צילום מצב
של המודל ההיסטורי מתוך lib/demo-market.json, ולא יחסים חיים או התחייבות להחזר.
